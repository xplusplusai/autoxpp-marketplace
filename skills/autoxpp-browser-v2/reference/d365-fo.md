## Session Management

### Session Expired Dialog
When D365 shows "Session ended" dialog:
1. Take snapshot → find "Start new session" button ref → click it
2. SSO may auto-authenticate — check snapshot after click
3. Only ask user to manually sign in if the button leads to a login page
4. After session recovery, navigate back to the form URL (`?mi=` parameter)

### Session Timeout Prevention
- D365 sessions expire after ~20 minutes of inactivity
- During long build/deploy cycles, the session WILL expire
- **Mitigation with persistent profile**: Use `playwright-cli open --persistent` to keep profile data between restarts
- If session expired, re-run auth flow from wrapper skill Section 2

### Auth Invalidation After Deployment
D365 deployments restart environment services ("Starting services on the environment" in VS Output window). This **invalidates ALL server-side sessions** — saved auth state cookies become stale even if they haven't expired.

After any deployment that shows "Starting services":
1. **Do NOT attempt** `state-load` — it will fail silently (redirect to login)
2. **Ask user to log in manually** in the browser
3. **Re-save** auth state after successful login
4. Then proceed with testing

### CRITICAL: When User Gives a Menu Path, Follow It

When the user provides an explicit menu path (e.g., "Credit and Collections > Inquiries and reports > Customers > Customer Aging Report"), **follow that path via menu tree navigation**. Do NOT try:
- `?mi=` URL shortcuts (fails for Output/Report menu items)
- D365 search bar (unreliable with playwright-cli, focus issues)
- Desktop skill clicking (unnecessary when browser skill works)

### Menu Tree Navigation Pattern (JS eval — reliable)

D365 nav tree uses `[role="treeitem"]` elements. Playwright-cli `ref=eXX` goes stale after every DOM change, so use JS eval with index-based clicking:

```bash
# Step 1: List all treeitems to find indexes
playwright-cli eval "[].slice.call(document.querySelectorAll('[role=\"treeitem\"]')).reduce(function(a,el,i){return a+i+':'+el.textContent.trim().substring(0,30)+'|'},'') + 'END'"

# Step 2: Click by index (e.g., Modules = 14)
playwright-cli eval "void(document.querySelectorAll('[role=\"treeitem\"]')[14].click())"

# Step 3: Wait for expand, re-list to get new indexes
sleep 2
# Repeat step 1 to see expanded children

# Step 4: Click next level (e.g., Credit and collections = 15)
playwright-cli eval "void(document.querySelectorAll('[role=\"treeitem\"]')[15].click())"

# Continue until you reach the leaf level with links
```

**For leaf-level links** (actual menu items like "Customer aging report"):
```bash
playwright-cli eval "void([].slice.call(document.querySelectorAll('a')).filter(function(a){return a.textContent.trim()==='Customer aging report'})[0].click())"
```

**For SSRS report dialogs** (opened from menu):
- Parameters dialog uses standard D365 form controls
- Fill fields with `playwright-cli type` (Tab between fields)
- Submit with `playwright-cli press Alt+Enter` (OK button hotkey)
- Wait 15-20s for report to render

## Form Interactions

### Grid Data Entry Pattern
D365 grid controls require specific interaction patterns with playwright-cli:
1. `playwright-cli snapshot` → find cell ref in YAML
2. `playwright-cli click {cell-ref}` → activates edit mode (shows input border)
3. `playwright-cli fill {cell-ref} "value"` or `playwright-cli type "value"`
4. For lookup fields: type value → snapshot → find dropdown item ref → click it
5. `playwright-cli press Tab` → move to next field (auto-scrolls grid horizontally)

### Enum/ComboBox Fields (e.g., NoYes dropdown)
- Default click on dropdown arrow may not open it in grids
- **Working pattern**: Triple-click to select text → type new value (e.g., "Yes") → click dropdown item ref
- D365 filters the dropdown list as you type

### New Record Creation
- Snapshot → find "+ New" button ref → click
- Cursor lands on first editable field
- Fill fields left-to-right using Tab
- `playwright-cli press Control+s` to save

### Grid Scrolling
- Grid auto-scrolls horizontally as you Tab through fields — **most reliable method**
- `playwright-cli press Tab` navigates through fields AND scrolls
- Manual scroll attempts (mousewheel, scrollbar) often don't work on D365 grids
- Some columns may be off-screen — Tab through to reach them

## Known Quirks & Workarounds

| Issue | Workaround |
|:------|:-----------|
| D365 dialogs are NOT native browser dialogs | Do NOT use `dialog-accept`. Snapshot → find button ref → click it |
| "Please wait" overlay blocks interaction | Option A (proactive): inject MutationObserver — see code below. Option B (reactive): poll snapshot until overlay gone |
| Typing into inactive grid cell does nothing | Must click cell ref first to activate edit mode |
| **`playwright-cli type` sends to active cell** | **Always use `fill {ref} "text"` with explicit element ref.** `type` sends keystrokes to whatever control has focus — often the wrong grid cell. `fill` targets a specific element. |
| **`Alt+F9` triggers Delete in D365** | **NEVER use Alt+F9.** Use `Alt+Shift+F4` to toggle between header/line view on detail forms. |
| **Form sections hidden by personalization** | Clear personalization: Options (action pane) > Personalize this page > More > **Clear** > Yes. Reload page after. Common on SO form where lines pane disappears. |
| **`playwright-cli open` defaults to headless + bundled Chromium** | **Always use `playwright-cli open --browser chrome --headed --persistent`** for D365 — system Chrome has saved passwords and is SSO-trusted; `--headed` lets user see/interact; `--persistent` retains auth across restarts. Omit `--browser chrome` only if Chrome is not installed (falls back to bundled Chromium). |
| **Browser not visible when login needed** | Must bring playwright Chromium to foreground via Win32 API (ShowWindow + SetForegroundWindow) BEFORE telling user to log in. |
| Auth expires after deployment (services restart) | Must re-login manually; saved auth state cookies are invalidated server-side |
| Auth expires after ~20 min inactivity | Save auth state after every successful login |
| Session expires during build/deploy | Try "Start new session" button first via snapshot+click, then ask user if needed |
| Multi-select in grids | Ctrl+click on row cells (not checkbox column) |
| Grid horizontal scroll doesn't respond to mousewheel | Use Tab to auto-scroll, or click-drag the grid scrollbar |
| "Trace inventory dimensions" dialog is NOT for grid columns | That's for tracing. Grid columns controlled by form dimension settings |
| **Entity SQL view broken after deploy** | Run Full DB Sync in VS (Ctrl+R, Ctrl+D). Takes ~15-25 min. Symptoms: "Cannot select a record" on forms or OData. |
| **Wave runs in batch after release** | Wait 10-15s before querying WarehouseWorkHeaders via OData for the new Work ID |
| Grid "No results" after quick filter | Quick filter may not match all columns — click **Show filters** and use column-specific `Filter field:` comboboxes |
| **Snapshot directory varies with CWD** | `playwright-cli` writes `.playwright-cli/` relative to shell CWD. If CWD changes, snapshots scatter across folders and `ls -t` returns stale files. **Fix:** Always use absolute paths: `SNAPDIR="C:/{workspace}/.playwright-cli"` and `SNAP=$(ls -t $SNAPDIR/page-*.yml \| head -1)`. Or cd to a consistent directory before starting. |
| **Action search "no results" for line-level actions** | D365 action search (e.g., "Reservation") only returns line-level actions when the lines FastTab is rendered in the DOM. If the lines pane is hidden by personalization, those actions simply don't appear. Must clear personalization AND toggle to detail view (`Alt+Shift+F4` after selecting a grid row) first. |
| **`Alt+Shift+F4` requires row selection** | The header-to-detail view toggle only works when a grid row is selected/focused. Click the row FIRST, then press `Alt+Shift+F4`. Without a selected row, the shortcut does nothing. |
| **Clearing personalization doesn't persist** | D365 may re-apply view personalizations on next navigation if the "Standard view" has unsaved changes (asterisk `*`). After clearing, explicitly save the view to make it stick. |
| **Auth expires after EVERY deploy** | D365 deployments restart environment services, invalidating ALL sessions. Use `playwright-cli open --browser chrome --headed --persistent` to maintain a persistent browser profile that can be re-authenticated once. System Chrome's saved passwords enable auto-login after re-auth. |
| **Item defaults Site from item setup** | In movement journals, filling Item number auto-fills Site/Warehouse from item's default settings (may be wrong for your test). Always explicitly set Site and Warehouse AFTER filling Item number. |
| **OData PATCH ignores some SO line fields** | `OrderedSalesQuantity` on `SalesOrderLines` is silently ignored by PATCH. Some fields are read-only via OData even though no error is returned. Use the browser for those updates. |

## "Please Wait" Overlay Removal (MutationObserver)

```bash
playwright-cli eval "(() => { const obs = new MutationObserver(muts => { document.querySelectorAll('.cl-busy, [data-dyn-role=\"BusyIndicator\"]').forEach(el => el.remove()); }); obs.observe(document.body, {childList: true, subtree: true}); return 'overlay-remover installed'; })()"
```

Inject once at session start. Auto-removes blocking overlays as they appear.

## Action Search — Finding Line-Level Actions

Many D365 actions (Reservation, Fulfillment, Intercompany) are nested deep in line-level menus (e.g., Sales order lines > Lines > Inventory > Maintain). These are NOT accessible from the header action pane.

**Reliable pattern — use action search:**
1. Press **Escape** to deselect any active grid cell (prevents typing into grid)
2. Click **"Search for an action"** button (magnifying glass icon in action pane)
3. Use `playwright-cli fill {searchbox-ref} "Reservation"` (**NOT** `type` — type sends keys to active grid cell)
4. Wait for results — options show as `option "Reservation Sales order lines > Lines > Inventory > Maintain"`
5. Click the option ref — navigates directly to the form

**Common line-level actions findable via action search:**
- `Reservation` — reserve inventory on a line
- `Batch reservation` — reserve specific batch
- `Marking` — mark inventory transactions
- `On-hand inventory` — check availability

## Sales Order Form Patterns

### Action Pane Structure
- Standard tabs: **Sales order** (default), **Sell**, **Manage**, **Pick and pack**, **Invoice**, **Warehouse**, etc.
- Some tabs may be under **"..."** overflow menu depending on viewport width
- **Release to warehouse** is under the **Warehouse** tab
- **Reservation** is a line-level action — use **action search** (see above)

### CRITICAL: List View vs Detail View

D365 SO form (`mi=SalesTable`) has **two distinct views**:

| View | What you see | Lines visible? | Action search finds Reservation? |
|:-----|:-------------|:---------------|:-------------------------------|
| **List view** | Header grid with SO rows. Action pane: Sales order, Sell, Manage... | **NO** — lines pane collapsed/hidden | **NO** — returns "no results" |
| **Detail view** | Single SO header + lines grid below. Shows "S000000086 : Customer Name" heading | **YES** — lines grid with items | **YES** — Reservation found |

**How to get to Detail view:**
1. Filter to your SO in the list view
2. Click the **SO number text** in the grid cell (ref for the textbox, e.g., `textbox "Sales order"`)
3. Press **Enter** — this follows the hyperlink and opens the detail view
4. **Verify:** Screenshot should show `"S000000086 : Customer Name"` heading with Lines/Header tabs and a lines grid below

**What does NOT work for opening detail view:**
- `?mi=SalesTable&SalesId=S000000086` URL parameter — does NOT filter or open detail
- Clicking the gridcell (just selects the row, stays in list view)
- `Alt+Shift+F4` from list view — toggles header sections but does NOT show lines
- Double-clicking the row — inconsistent behavior

**Once in detail view**, all line-level operations work:
- Action search finds Reservation, Batch reservation, etc.
- Warehouse tab shows Release to warehouse
- Lines grid shows items with qty, unit, etc.

### Sales Order Creation Flow
1. Navigate to `?mi=SalesTable` or click New on list page
2. "Create sales order" dialog — fill Customer account → Tab (wait for address)
3. Find "OK" button ref in snapshot → click (coordinate clicks unreliable on this dialog)
4. SO opens in **detail view** automatically (New creates and opens detail)
5. Find Item number cell ref → click → fill item number → Tab
6. Find Quantity cell ref → click → fill quantity → Tab
7. Tab through remaining fields to reach Site/Warehouse columns (off-screen right)
8. `playwright-cli press Control+s` to save
9. **Reserve** using action search (see above) → **Reserve lot** → **Back**
10. To add more lines: click **Add line** button, repeat steps 5-8
11. For subsequent visits: filter in list view → click SO number textbox → **Enter** to open detail

### Release to Warehouse Flow
1. Inventory must be reserved first (see Reservation pattern)
2. Open **Warehouse** tab in action pane (may be under overflow "...")
3. Find "Release to warehouse" button ref → click
4. Verify success message with Wave ID and Shipment ID in snapshot
5. **Wait 10-15s** for wave batch to run and create work
6. Query Work ID via OData: `GET /data/WarehouseWorkHeaders?$filter=SourceOrderNumber eq '{SO}'`

## Movement Journal Patterns (InventJournalTableMovement)

Used to add inventory for testing (WHS scenarios require on-hand before reservation).

1. Navigate to `?mi=InventJournalTableMovement`
2. Click **+ New** > Journal name defaults (e.g., IMOV) > **OK**
3. Click **Journal lines** heading to expand the lines section
4. Click **+ New** in lines toolbar to add a line
5. Fill: Item number → Tab → Site → Tab → Warehouse → Tab → Location → Tab → Quantity → Tab → Offset account
6. Click **Post** > Confirm dialog shows journal number > **OK**
7. May show quantity rounding dialogs ("must be multiple of X") — click **Yes** to accept
8. Financial dimension warnings during posting are non-blocking

## Lessons Learned

| Context | Learning |
|:--------|:---------|
| Grid data entry | D365 grid cells need explicit click activation before typing |
| Process button | D365 dialog buttons are DOM elements — use snapshot + ref click |
| Enum dropdowns | Triple-click → type value → click dropdown item |
| Session management | Always click "Start new session" before asking user to login — SSO may auto-authenticate |
| Confirmation dialogs | Dialog shows record count (e.g., "Reset status for 2 record(s)?") — find Yes button ref in snapshot |
| Multi-select | Ctrl+click on grid rows for multi-select; works on row content cells, not checkboxes |
| SO creation | Must Reserve (Inventory > Reservation > Reserve lot) BEFORE Release to warehouse |
| Warehouse release | "Release to warehouse" is under overflow (...) → Warehouse tab |
| Overlay blocking | D365 "Please wait" overlay blocks interaction — inject MutationObserver to auto-remove |
| SO line dimensions | Site/Warehouse columns off-screen right — Tab through fields to auto-scroll |
| Create SO dialog | OK button requires ref click from snapshot — coordinate clicks unreliable |
| Grid navigation | Ctrl+End jumps to last row — useful for finding newest records |
| Quick filter | D365 quick filter may not match all columns; use column-level filtering for specific records |
| **Ctrl+F3 Filter Pane** | Quick filter defaults to one column (e.g., "Product name" on Released Products, NOT "Item number"). Typing a value that belongs to a different column returns zero results. **Fix:** Press **Ctrl+F3** to open the Filter Pane — a side panel with explicit column dropdowns + operator + value. Select the correct column (e.g., "Item number"), operator ("begins with"), type the value, click **Apply**. This is the reliable way to filter by any column. Do NOT waste time trying `ItemId:value` syntax, URL `f=` params, or right-click column headers — none of those work. |
| **FO page load timing** | FO pages take 8-12 seconds to fully render after navigation. Snapshots taken immediately show minimal content (loading spinner). **Always sleep 8-12s before snapshotting** after any FO page navigation (`goto`, tab click, form open). |
| **Post-deploy first page load is slow** | After build+deploy, the environment restarts services and recompiles metadata. The **first** page load takes 30-90+ seconds (vs 8-12s normally) — the FO loading screen stays up while the environment warms up. **Do NOT poll `snapshot` in a tight loop during this.** Sleep 30s before the first snapshot attempt, then poll every 15s. Expect 2-4 polls before the page is ready. Subsequent page loads return to normal 8-12s timing. |
| SO creation dialog | Customer lookup requires clicking lookup icon — Tab alone doesn't trigger name/address resolution |
| OData via eval | Use %24 encoding for $ in playwright-cli eval OData URLs (shell strips bare $) |
| Grid verification | D365 grids use virtual scrolling (only visible rows in DOM) — use OData queries for data verification |
| Auth state | playwright-cli state-save/state-load works for D365 HttpOnly cookies; Chrome MCP v1 could not capture these |
| Menu navigation | `?mi=` URL does NOT work for Output menu items (reports). Use menu tree navigation instead. |
| Menu navigation | playwright-cli ref=eXX goes stale after DOM changes. Use JS eval with `document.querySelectorAll('[role="treeitem"]')[index].click()` for reliable nav tree clicks. |
| Menu navigation | When user gives explicit menu path, follow it literally via nav tree — don't try URL or search shortcuts. |
| Report dialogs | SSRS report dialog OK button uses `Alt+Enter` hotkey. Regular click/ref approaches fail. |
| Report dialogs | D365 OK button text may not be findable via `querySelectorAll('button')` — it renders with special D365 control markup. |
| `fill` vs `type` | `type` sends keystrokes to active control (often wrong grid cell). Always use `fill {ref} "text"` for targeted input. |
| Alt+F9 = Delete | Alt+F9 triggers Delete in D365. Use Alt+Shift+F4 to toggle header/line view. |
| Hidden form sections | Personalization can completely hide panes (e.g., SO lines). Fix: Options > Personalize > More > Clear. |
| Action search | Line-level actions (Reservation, etc.) aren't in header action pane. Use "Search for an action" button + `fill` the search textbox. |
| Movement journal | Full flow: New > IMOV > OK > Journal lines > New > fill fields > Post > OK. Quantity rounding and financial dimension warnings are non-blocking. |
| Headless browser | Always use `--browser chrome --headed --persistent` for D365. System Chrome has saved passwords; headless = user can't login. Bring browser to foreground via Win32 API before asking for login. |
| SQL view broken | After deployment, entity SQL views can become stale. Symptoms: "Cannot select a record" errors. Fix: Full DB Sync in VS (~22 min). |
| Stale snapshots | playwright-cli writes snapshots to CWD's `.playwright-cli/`. If CWD changes, you read stale files with wrong refs. Always use absolute `SNAPDIR` path. |
| Lines pane hidden | SO form lines pane hidden even after clearing personalization. Requires: 1) click grid row, 2) Alt+Shift+F4 to toggle. Action search returns "no results" for Reservation until lines load. |
| Persistent auth | Logged in 4+ times in one session due to deploy-triggered auth expiry. Use `--browser chrome --persistent` profile to reduce re-auth — system Chrome's saved passwords enable auto-login. |
| Item site default | Movement journal: item 100210 defaulted to HQ01/HQPL01MAT. Had to manually set Site=DC02, Warehouse=DC02 after item fill. |
| OData silent ignore | PATCH on SalesOrderLines.OrderedSalesQuantity silently returns success but doesn't update. Must use browser for qty changes. |
| Auto-login | With `--persistent` profile: fill email → Next → browser auto-fills password → click Sign in. Works for Microsoft SSO when credentials are saved in browser. Eliminates manual login. |
| Grid new record Tab order | Custom shipping-advice form Tab order example: Sales order → Line number → Work ID → Item number → Qty → Unit → Batch → Serial → Tracking → Mode → Ship Date → Gross Weight → Change reason → Description → Ready to process. Use `type` for sequential Tab-based entry. |
| Grid virtual columns | D365 grids don't render offscreen columns in DOM. After tabbing right, earlier columns (e.g., Work ID) become inaccessible via snapshot refs. Must fill fields in Tab order during record creation — can't go back. |
| SalesId EDT blocks TO numbers | `SourceOrderNumber` with EDT `SalesId` rejects TO numbers via OData. Form shows warning but accepts. Fix: `IgnoreEDTRelation=Yes` + `validateField` override on both table and staging table. |
| Phase A/B split failure recovery | When Phase A (work closure) succeeds but Phase B fails, work is permanently closed. Re-processing must detect closed work and skip Phase A: `if (workTable.WorkStatus == WHSWorkStatus::Closed) return;` |
| Transfer order menu item | `mi=InventTransferOrder` (singular). `mi=InventTransferOrders` gives "menu item does not exist". |
| **List vs Detail view** | SO form has two views. List view: header grid only, NO lines, action search can't find Reservation. Detail view: header + lines grid, everything works. **To open detail: click SO number textbox → press Enter.** This was the #1 stuck point — spent hours trying Alt+Shift+F4, clearing personalization, scrolling — none worked because we were in list view the whole time. |
| URL SalesId param | `?mi=SalesTable&SalesId=S000000086` does NOT open the detail view. It just passes through to the list view. Must filter + click SO number + Enter. |
| Screenshot before action | Always take a screenshot to verify current state BEFORE attempting complex interactions. Would have caught the list-vs-detail issue much earlier. |
| Item Requirements form | No direct `mi=ProjSalesItemRequirementList` URL — gives "menu item does not exist" error. Navigate: `ProjProjectsListPage` → select project → Plan tab → Item requirements button. |
| `press` not `keyboard` | `playwright-cli keyboard Enter` is invalid. Correct command: `playwright-cli press Enter`. |
| **FixedDataTable grid — row-select checkbox** | D365 list-page grids (`.fixedDataTable`) have frozen left column with row-select checkbox (no aria-label) and scrollable right area with data. To click checkbox from a data cell: `const row = dataInput.closest('.fixedDataTableRowLayout_rowWrapper'); row.querySelector('[role=checkbox]:not([aria-label])').click();` The `:not([aria-label])` excludes data checkboxes (which have labels like "IC Sales Order Created"). |
| **Batch disposition code READONLY on InventBatch UI** | On the InventBatch list/detail form (Inventory management > Tracking dimensions > Batches), the Batch disposition code field is readonly at the DOM level (`input.readOnly === true`). Only "Reset batch disposition code" action is available — no "Change disposition" action. To test blocked batches: pre-seed via admin workflow, or ask admin to enable the privilege, or flip `InventBatchDispositionMaster.Available` (broad impact). |
| **Filter Pane Apply button y-position shifts** | The Apply button in the filter pane (Ctrl+F3) changes y-position when the message bar (info/warning) is visible above it. **Always re-query `getBoundingClientRect()` immediately before clicking Apply** — cached position from prior state will miss. Typical shift: y≈375 (no bar) vs y≈440 (bar visible). |
| **Filter Pane Apply button required** | Entering a value in the filter pane and pressing Enter does NOT reliably apply the filter. Must click the **Apply** button at the bottom of the filter pane. |
| **SysBoxForm invisible to snapshot** | D365 `SysBoxForm` confirmation dialogs (Reset Status, Process, Delete) render as a `LightBox` overlay that blocks all clicks but does NOT appear in `playwright-cli snapshot`. Symptom: click timeout with "SysBoxForm subtree intercepts pointer events". **Detection:** `eval "document.querySelector('[data-dyn-form-name=\"SysBoxForm\"]') ? document.querySelector('[data-dyn-form-name=\"SysBoxForm\"]').innerText : 'NO_DIALOG'"`. **Click buttons:** `eval "document.querySelector('[data-dyn-form-name=\"SysBoxForm\"] button[name=\"Yes\"]').click()"`. Check after any action button click that returns OK but subsequent clicks time out. |
| **`eval` requires ES5 syntax** | `playwright-cli eval` with `Array.from()` or arrow functions (`=>`) throws `TypeError: result is not a function`. **Fix:** Use `[].slice.call(nodeList)` instead of `Array.from(nodeList)`, and `function(x) { return ... }` instead of `x => ...`. Also: `run-code` with Playwright API calls (`page.locator`, `page.getByRole`) throws the same error — only raw JS via `eval` works for page interaction. `JSON.stringify()` also fails for complex return values — join results as a delimited string instead. |
| **ref-based click/fill fails on D365 pages** | `playwright-cli click ref=eXXX` and `fill ref=eXXX` consistently return "ref not found" on D365 F&O pages even though the snapshot YAML file contains valid refs. Root cause: D365 content loads in a way that makes the snapshot refs stale between capture and use. **Workaround:** Use `eval` with DOM queries for ALL interactions: focus via `eval "document.querySelector('selector').focus()"`, type via `playwright-cli type "text"`, click via `eval "document.querySelector('selector').click()"`. This was 100% reliable on Table Browser and filter pane interactions where ref clicks failed every time. |
